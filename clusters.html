Graph Clustering Methodology

GRAPH CONSTRUCTION:
- Nodes: Wallets appearing in holder × trader intersection
- Edge weights based on 6 heuristics (each adds to connection strength)

EDGE HEURISTICS (applied with thresholds):
1. Shared Funding Source (weight +3)
   - Same first inbound SOL/USDC within 30-min window
   - Detected via feePayer analysis and transaction graph

2. Shared CEX Off-Ramp (weight +2)
   - Same known CEX deposit address interactions
   - Limited detection due to data constraints

3. Shared Router/Program (weight +2)
   - Identical swap route/program combo
   - e.g., both use Raydium (DF1ow4...) + Jito consistently

4. Synchronized Behavior (weight +4)
   - Buy within 60s + sell within 5min across 2+ events
   - Identical timestamps = strongest edge type

5. Shared Hub Wallet (weight +3)
   - Both route through same intermediate before buying
   - Fee-payer relationships (one pays for other's tx)

6. Dusting/Consolidation (weight +1)
   - Frequent small transfers among cluster wallets
   - Limited visibility in sample data

COMMUNITY DETECTION:
- Connected components after applying weight threshold ≥5
- Clusters require minimum 1 strong edge or 2+ moderate edges

AGGREGATE METRICS:
- Total realized P&L: Sum of estimated SOL gains per cluster
- Median ROI: Middle value of wallet ROI multiples
- Win rate: % of wallets with realized gains > 1x
- Cross-token: Count of tokens where cluster appeared
